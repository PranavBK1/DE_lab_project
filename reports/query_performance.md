## Why question (c) uses a materialized view

Computing (c) directly from `tags` × `movie_genres` (count DISTINCT users per genre and tag) takes **9,638 ms** (median of 5). `mv_popular_tags_genre` stores those counts, so the query only ranks them. Tags cannot be edited in the app, so precomputing is safe; `etl/load.py` rebuilds the view on every load.
